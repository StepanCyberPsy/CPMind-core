# Задел: интерактивный креатив SIMID 1.2

**Статус: не подключён к продукту.** Точка входа `../simid.ts` не входит в
сборку (`build.ts`), схема отчёта `@cpmind/shared/schemas/simid.ts` не входит
в публичный экспорт пакета. Бэкенд не выдаёт `<InteractiveCreativeFile>`,
приёмника отчёта не существует. Код исполняется только в тестах.

Задел сохранён потому, что протокольная часть верна и переиспользуема, если
площадки клиента начнут отдавать действительно интерактивные креативы. Тогда
SIMID уместен как креативная технология, а измерение CPMind продолжает ехать
через OMID, без связи с этим кодом.

## Почему не подключено

Разбор SIMID 1.2 показал, что механизм не предназначен для измерения и его
применение по этому назначению упирается в три ограничения.

**1. Клик по рекламе.** SIMID 1.2 §4.3.10.1 и §6.9: плеер делает iframe
креатива видимым, получив `resolve` на `SIMID:Player:startCreative`, и для
видеорекламы обязан растянуть его на весь медиаэлемент — «position the iframe
over media element at player's upper-left corner and set iframe dimensions to
media's width and height». Кросс-доменный iframe перехватывает клик, и изнутри
это не исправляется: `pointer-events: none` на границу iframe не действует.
При этом §4.4.1 возлагает исполнение clickthrough на креатив: «SIMID delegates
clickthrough execution to the creative, including redirecting the user to the
landing page». Делегировать переход обратно плееру (`playerHandles: true`)
разрешено только при `navigationSupport === 'playerHandles'`, а §4.4.12 прямо
указывает: «In web environments, the creative manages navigation».

Отсюда два исхода, и оба неприемлемы для вендора измерений:

- ответить `resolve` и взять клик на себя — `window.open` из iframe зависит
  от атрибута `sandbox`, выставляемого плеером, а отказ недетектируем:
  `SIMID:Creative:clickThru` не имеет ответа, когда переход выполняет креатив
  (§4.4.1 — `resolve` приходит только если переход делает плеер). Revenue-
  критичный путь с молчаливыми отказами;
- не отвечать на `startCreative` — iframe остаётся скрытым, реклама не
  затронута, события `SIMID:Media:*` продолжают приходить (они зависят от
  `resolve` на `init`, а не на `startCreative`). Но спецификация нигде не
  обещает, что плеер продолжит их посылать креативу, не ответившему на
  обязательное сообщение, а §4.3.10.2 разрешает плееру выгрузить iframe при
  `reject` — конформная реализация вправе так же трактовать молчание. Плюс
  плеер по завершении медиа отправляет VAST error 1213 на каждом показе.

**2. Покрытие сценариев.** `<InteractiveCreativeFile>` находится в
`<MediaFiles>` внутри `<InLine>`. В сценарии «CPMind оборачивает чужой тег»
InLine нам не принадлежит, поэтому механизм работает только в сценарии
«CPMind выдаёт свой тег» — половина требования.

**3. Приобретаемые сигналы.** Поверх OMID SIMID добавляет фактически один
наблюдаемый сигнал: перемотку назад как свидетельство повторного просмотра
(`replay_count`, сейчас записан нулём и задокументирован как ненаблюдаемый).
Остальное — `timeupdate` мельче квартилей и `skippableState`; видимости,
геометрии и окружения страницы SIMID не даёт вовсе.

## Состав задела

- `protocol.ts` — транспорт §8.1.1: кадрирование сообщений, разбор входящих,
  `createSession` с криптостойким идентификатором (§8.4), `resolve`/`reject`
- `accumulator.ts` — чистый накопитель состояния воспроизведения по позиции
  плейхеда. Интервал относится к состоянию звука на момент предыдущего
  события — та же договорённость, что в S1/S2 основного SDK. Приращение
  больше `MAX_FORWARD_DELTA_SEC` считается перемоткой, а не просмотром
- `report.ts` — сборка отчёта в контракте `SimidReportSchema`; `-1` из SIMID
  («неизвестно») приводится к `null`
- `../simid.ts` — клиент: рукопожатие, разбор `environmentData` и
  `adParameters`, подписка на `SIMID:Media:*`, отправка отчёта на завершении

## Инфраструктурное ограничение при подключении

HTML-оболочку креатива плеер загружает в iframe. Блок `location /` для
`delivery.cpmind.tech` в `nginx/nginx.conf` отдаёт `X-Frame-Options: DENY`,
поэтому оболочка, выданная бэкендом по этому хосту, во фрейм не встанет.
Подключение задела требует либо отдельного location без этого заголовка, либо
публикации оболочки как файла на CDN.

## Чего в заделе нет

Приёмника `POST /api/collect/simid`, колонок в `ad_sessions`, HTML-оболочки
креатива, выдачи `<InteractiveCreativeFile>` и `<AdParameters>` из `inline.ts`,
публикации бандла в `runtime-publisher`.

Отдельно: отчёт SIMID по построению является диагностикой рекламной сессии и
в показ не сворачивается. Показ по тому же сеансу пишет ветка OMID, и
объединение двух источников — самостоятельная задача со своими правилами
приоритета.
