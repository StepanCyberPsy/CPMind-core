## Критичное (блокирует калибровку весов)

**P-14 — S4 не учитывает уход вкладки в фон.**
Стенд B01 (фоновая вкладка): `tab_active_time_ms` = `tab_total_time_ms` во всех строках, S4 = 100 у 100% показов, хотя вкладка реально уходила в фон (desktop и mobile).
Нужно: слушать `visibilitychange`, останавливать счётчик `tab_active_time_ms`, пока вкладка скрыта.

**P-15 — F_Presence не обнуляет «мёртвый» показ.**
Стенд B02 (показ открыт, бездействие >60 сек, в одном прогоне >2 мин): F_Presence = 1 у всех строк, Score 54–64 вместо 0. Поле `time_since_last_event_ms` пустое во всех строках, поэтому условие обнуления не выполняется.
Нужно: заполнять `time_since_last_event_ms`; проверить срабатывание обнуления F_Presence на реально брошенной вкладке.

**P-16 — скролл не считается, пока баннер ниже середины экрана.**
Стенд B03b (баннер внизу страницы): `scroll_speed` = 0 и вся скролл-группа (streaks, direction_changes, pause_count, std_dev) = 0, хотя скролл был. На стендах с баннером в середине/верху скролл фиксируется (A01 100%, A02 91%, A03 95% строк). Следствие: S3 недостоверен для любого размещения ниже первого экрана.
Нужно: слушать скролл с момента загрузки страницы (или появления баннера в DOM), а не с момента пересечения середины экрана.

**P-17 — на mobile измерение крупного баннера не стартует без зум-аута.**
Стенд B05b (большой баннер): на мобильном запись на бэкенд пошла только после уменьшения масштаба пользователем; до этого S1 не считался. Все мобильные строки с `zoom=true`.
Нужно: считать видимость по доле вьюпорта, занятой баннером, а не по доле самого баннера; баннер крупнее экрана должен стартовать измерение.

## Среднее

**P-01 — S3 ломается на медленном чтении (двойной штраф streaks).**
A02 (вдумчивое чтение): S3 = 10, почти как у пролёта мимо (A01: S3 = 0). Причина: `streak_penalty = min(20, streaks×8)` при streaks≥3 даёт −20 и съедает базу. A03 (возврат): S3 = 0 даже при сработавшем return_bonus. A04 (мало streaks): S3 = 54 — формула рабочая, проблема в штрафе.
Нужно одно из: считать streaks только для быстрых скроллов; не штрафовать при `scroll_speed_avg` < 300; пересмотреть коэффициент.
Вес S3 не калибруем, пока не починен.

**P-02 — двойной штраф momentum + streaks на mobile.**
A01: `is_momentum_scroll` = true у 100% mobile-показов. Инерция пальца засчитывается как «пролистал не глядя».
Нужно: на mobile при `is_momentum_scroll=true` смягчать/не применять streak_penalty; пересмотреть пороги скорости для mobile.

**P-03 — mobile не получает S5 за hover.**
A02: на desktop hover≥1000мс → S5=50 у 29/30; на mobile уровней hover нет (0/28). S5>0 у 19/28 mobile против 30/30 desktop.
Нужно: ввести mobile-аналог удержания (долгий тап / `touch_start_end_delta`) как уровень S5; либо device-aware шкала S5.

**P-06 — нет валидации `campaign_id`.**
На приёмке кампания прошла с кириллицей и кавычками.
Нужно: мягкая валидация `[A-Za-z0-9_]` в теге/бэкенде.

**P-13 — генератор стенда A04 не вешает клик на desktop.**
A04: `clicked=true` только у mobile-строк; desktop-ветка S5=100 (clicked→100) не покрыта. Перепрогон не делаем.
Нужно: при доработке стендов навесить клик на desktop-обработчик.

**P-18 — случайный zoom/swipe даёт S5=90.**
B04, B05b, C03: zoom или swipe>0 → S5=90 (почти как клик). На mobile жест часто случайный.
Нужно: понизить вес одиночного zoom/swipe или требовать подтверждающий признак (удержание/повтор zoom, swipe по баннеру).

**P-19 — `competing_ads_visible` = 0 на стенде «теснота» (на проверку).**
B04: поле = 0 во всех строках, штраф S7 за захламлённость не сработал.
Нужно: уточнить, как считается `competing_ads_visible`; перепроверить стенд.

**P-05 — рассинхрон таймеров S4** (`tab_active_time_ms` > `tab_total_time_ms`, до 105%) на коротких показах. Кэппинг до 100 спасает Score. Глянуть источник смещения.
