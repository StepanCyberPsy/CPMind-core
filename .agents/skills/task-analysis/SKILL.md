# Task Analysis

## Preconditions
Read `AGENTS.md`, `docs/engineering/DEVELOPMENT_WORKFLOW.md`, and the applicable protocol(s) in `docs/engineering/references/`. Confirm this is the active stage and prior gates are satisfied. If prerequisites are missing, stop and ask.

## Procedure
1. Determine whether this is a new build, existing modification or resumed work using Stage 0 results.
2. Translate the request into observable behavior, nonfunctional constraints, exclusions and success criteria; distinguish user facts from assumptions.
3. Identify stakeholders, system boundaries, security/data/performance considerations and risk tier. Do not invent SLAs, scale targets or product requirements.
4. Ask only blocking questions; offer explicit options for unresolved decisions.
5. Produce a concise task definition with numbered acceptance criteria, out-of-scope items, dependencies and unknowns.
6. Request explicit Stage 1 approval; do not advance or write product files.

## Output and exit
Provide the stage deliverable, evidence labels and paths, uncertainties, status, and exact next approval or action. Apply the workflow's stage transition; never infer approval.
