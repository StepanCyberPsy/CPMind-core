## 2. Продукт

### 2.1 Назначение

**CPMind** — платформа измерения качества рекламного показа. Для каждого показа собираются 7 поведенческих сигналов (S1–S7). Каждый переводится в шкалу 0–100 калибруемой моделью, затем взвешенно объединяется в **CPMind Score (0–100)** с учётом фактора присутствия F_Presence и IVT-классификации (невалидный трафик).

| Сигнал | Что измеряет | Модель нормализации | Разбиение моделей |
|---|---|---|---|
| S1 | Время в зоне видимости | Weibull (MLE) | `устройство\|группа креатива` → группа → `global` |
| S2 | Доля экрана | Без калибруемой модели | — |
| S3 | Скорость и паттерн скролла | Логистическая регрессия (IRLS) | `устройство\|группа креатива` → группа → `global`; с учётом версии констант |
| S4 | Активность вкладки | Экспоненциальный штраф (λ, T_ref) | `desktop_banner`, `mobile_banner`, `desktop_video`, `mobile_video`, `default` |
| S5 | Взаимодействия | Логистическая регрессия | `desktop`, `mobile_tablet` → `global`; с учётом версии констант |
| S6 | Вовлечённость в видео и звук | Логистическая регрессия | `устройство\|группа размещения` (раздел 5.10); с учётом версии констант; для баннеров `null` |
| S7 | Контекст страницы | Квантильные пороги | по устройству → `global` |

**Веса** — глобальная активная версия отдельно для баннеров и видео. Стартовые значения:
- баннеры: S1 0.30, S2 0.20, S3 0.15, S4 0.15, S5 0.15, S6 0.00, S7 0.05;
- видео: S1 0.15, S2 0.10, S3 0.10, S4 0.10, S5 0.10, S6 0.40, S7 0.05.

Вес недоступных (`null`) сигналов перераспределяется пропорционально. Калибровка весов пересчитывает Score исторических показов.

### 2.2 Три уровня настройки расчёта

| Уровень | Что определяет | Как выбирается |
|---|---|---|
| Константы сбора (`tag_constants_configs`, версии `v0…v4`) | 19 порогов сбора в браузере и `PRESENCE_IDLE_TIMEOUT_MS` на сервере | Версия по умолчанию + необязательное закрепление в плейсменте (раздел 5.9) |
| Модели сигналов (`s1_weibull_configs`, `s3/s5/s6_logistic_configs`, `s4_configs`, `s7_quantile_configs`) | Перевод сырого значения в 0–100 | Задача рекалибровки создаёт черновик, администратор вручную активирует. Применяется к сегменту, не к плейсменту |
| Веса (`weight_configs`) | Вклад S1–S7 в Score | Одна глобальная активная версия на категорию (баннер/видео) |

### 2.3 Режимы измерения

- **legacy_tag** — прежний встраиваемый тег (`packages/tag`). Больше не размещается, но данные и логика сохранены.
- **Hosted-доставка через SDK** — embed-скрипт, VAST, плеер (`packages/player`), display-runtime (`packages/display-runtime`):
  - `full_cpmind_player` — видео в плеере CPMind;
  - `full_direct_display` — баннеры, включая HTML5 (после блока C);
  - `vast_only` — VAST без плеера CPMind, не измеряется.

### 2.4 Монорепозиторий

| Пакет | Назначение |
|---|---|
| `shared` | Zod-схемы контрактов, типы, формулы нормализации и Score, общие утилиты |
| `sdk` | Сбор сигналов S1–S7, присутствие, транспорт, сегментация показов |
| `tag` | Legacy-тег (сборка с константами версии через esbuild define) |
| `backend` | Fastify API: приём показов, scoring, IVT, доставка (embed/VAST/события), админка, фоновые задачи |
| `frontend` | Next.js 14, панель администратора и пользователя |
| `media-worker` | Обработка загрузок: видео (FFmpeg), баннеры, HTML5-бандлы |
| `embed` | Loader, подгружающий нужный runtime |
| `display-runtime` | Рендер баннеров (static/gif/HTML5) и измерение |

## 3. Инженерный контракт (`ENGINEERING_INSTRUCTIONS.md`, действует)

- Только SOTA, production-ready, enterprise-grade код: без заглушек, допущений и макетов.
- Источник истины — реализованный код и зафиксированные решения. При нехватке контекста работа останавливается и запрашиваются конкретные файлы.
- Формат изменений: **Before/After**, последовательно, пункт за пунктом. В блоке Before нет сокращений через многоточие. Большие изменения — полная замена файла.
- Отступы: 4 пробела в новых файлах, в изменяемых — стиль файла (часть backend-файлов использует 2 пробела).
- Длинных разделительных строк нет. Вокруг операторов по одному пробелу. У многоаргументной функции каждый аргумент на отдельной строке.
- Комментарии в коде и ответы — **на русском языке**.
- Код валидируется до представления. Тесты Vitest пишутся только для новой и изменённой логики (автотестов исторически не было).

## 5. Принятые архитектурные решения

### 5.1 Таксономия размещений (задача 1.4, не реализована)

Два уровня: формат → подтип, один подтип на плейсмент.
- **`banner`** (бывший `display`) — без подтипа.
- **`instream`:** `preroll`, `midroll`, `postroll`, `pauseroll`. Только через плеер CPMind.
  - `midroll` срабатывает при 50% длительности контента, один раз за просмотр.
  - `pauseroll` показывается при первом возобновлении после паузы, один раз за просмотр.
- **`outstream`:** `inpage` (бывший `standalone_video`) и `sticky`.
  - Оба зациклены. В случайном режиме один ролик не повторяется подряд.
  - `sticky`: угол + смещение в px, ширина и высота. Мобильная конфигурация уточняется на этапе 2.
- **`plcmt`** вычисляется по подтипу (OpenRTB 2.6): instream → 1, inpage/sticky → 2. Пользователь его не задаёт.
- **Хранение:** колонки `format` и `subtype` с CHECK в `placements`, `ad_sessions`, `impressions`. Enum `delivery_mode` пересоздаётся. Старые значения временно сохраняются для существующих данных.

### 5.2 Несколько видео в плейсменте (задача 1.5, не реализована)

- Только видео, баннеры остаются с одним креативом.
- Все ролики — из одной кампании и одного плейсмента. Каждый ролик — отдельный креатив со своей версией и ассетами.
- Новая таблица набора роликов: `placement_id`, `creative_id`, `weight_pct` (0–100), `display_order`. Сумма весов строго 100%, веса задаются вручную.
- **In-stream:** один ролик на рекламную возможность, взвешенный случайный выбор.
- **Out-stream:**
  - последовательно по кругу (1→…→N→1);
  - или взвешенно случайно без повтора подряд.
- Каждый показ ролика — новый `session_group_id` и порядковый номер в `ad_session` (`video_show_index`).

### 5.3 Звук и контролы (задача 2.2)

- **In-stream:** всегда стартует со звуком, контролы полные (перемотка, пауза, skip, звук).
- **Out-stream:** стартует без звука, контролов нет, кроме кнопки звука и закрытия.
- Пользователь может переопределить звук по умолчанию: поля `initial_muted` и `initial_muted_overridden`. Переопределения контролов нет.

### 5.4 Идентификаторы (задача 1.3)

- `campaign_id` в показе — название кампании. Задаётся при создании, неизменяемо, уникально на пользователя (регистронезависимо).
- `creative_id` в показе — пользовательский `creative_key`, иначе системный UUID. Отдельного `external_id` нет.
- `publisher_domain`: переопределение в плейсменте → домен, определённый SDK → NULL (в UI «—»).
- Legacy-поля сохраняются. Атрибуция hosted-показа берётся из `ad_session`.

### 5.5 Иерархия сессий

```
ad_session (ad_session_id)         — одна рекламная возможность: кампания, плейсмент, формат, подтип
  └─ показ ролика (session_group_id)  — конкретный креатив из набора
       └─ сегмент (impression_id)     — интервал измерения (разбивка по простою)
```

- **Баннер:** один показ, один или несколько сегментов.
- **In-stream:** один ролик на `ad_session`. Сессия создаётся в момент вставки, **не** при загрузке страницы.
- **Out-stream:** несколько показов роликов в одной сессии, каждый цикл — новый `session_group_id` с номером.

### 5.6 Нарушения контекста при приёме показа

- **Жёсткий отказ (422):**
  - сессия не найдена;
  - чужой владелец;
  - сессия старше `AD_SESSION_TTL_HOURS` (по умолчанию 24 ч, максимум 168 ч);
  - `vast_only`;
  - неполный контекст.
- **Мягко (показ принимается, ставится флаг в `context_violations`):**
  - плейсмент неактивен;
  - креатив сменился;
  - `CLIENT_CONTEXT_MISMATCH` — клиент заявил контекст, отличный от сессии, включая версию констант.

### 5.7 Поведение сбора (исправления К1)

| Событие | Поведение |
|---|---|
| Вкладка скрыта | Промежуточный снимок (тот же `impression_id`, `is_checkpoint = true`), измерение продолжается |
| `pagehide`, завершение | Финальная отправка с причиной (`finalization_reason`) |
| Клик | Промежуточный снимок не чаще раза в секунду, **не** завершение |
| Сервер: upsert снимка | `ON CONFLICT (impression_id) DO UPDATE` только если строка — снимок, `ad_session_id` совпадает и `timestamp_end` не уменьшается |
| Видео не стартовало | Записи в `impressions` нет, в `ad_session` пишется `autoplay_outcome = blocked` |
| Досмотр S6 | Только фактически просмотренный отрезок (`watchedFrontierSec`), перемотка вперёд не засчитывается |
| Флаги звука | `unmuted_by_user` и `muted_by_user` — только по действию зрителя, `start_muted` — состояние при первом старте |
| Окно измерения hosted | Начинается с подтверждённого первого кадра |

### 5.8 Измерение HTML5 (двухуровневое доверие)

Код рекламодателя исполняется в одном окне с мостом и может подделать любое сообщение. Поэтому события моста принимаются только при подтверждении со стороны страницы:

| Событие моста | Устройство с курсором | Сенсорное устройство |
|---|---|---|
| `click`, `tap` | Курсор над iframe или фокус iframe; `userActivation` не `false` | `userActivation.isActive` (или фокус) и iframe виден не менее чем на 50% |
| `activity`, `swipe`, `zoom` | Только курсор над iframe | iframe виден и прошло не более 30 с с последнего доверенного события; окно этими событиями не продлевается |

- Клик внутрь iframe фиксируется самой страницей через `window.blur` и `activeElement === iframe`.
- Отклонённые события попадают только в диагностическое поле `unconfirmed_frame_events`.
- Активность из iframe сбрасывает таймер простоя, но не пишется в интервалы IVT.
- HTML5 → `full_direct_display`. Протокол моста — версия 2, совместим с версией 1.

### 5.9 Версии констант сбора (реализовано в 1.2)

- Ровно одна **версия по умолчанию** (`is_default`), она всегда активна. Новая версия создаётся активной, но **не** становится версией по умолчанию.
- **Закрепление версии в плейсменте** (`placements.tag_constants_config_id`) — только администратор, иначе 403. Закреплять можно только активную версию.
- **Деактивация запрещена (409)** для версии по умолчанию и для версии, закреплённой за плейсментами. Версии никогда не удаляются.
- **Версия фиксируется в `ad_sessions.tag_constants_version`.** Показы идущих сессий принимаются по ней в пределах окна приёма даже после деактивации.
- **Конкурентность:** advisory-lock плюс `FOR UPDATE` при деактивации и смене версии по умолчанию, `FOR SHARE` при закреплении.
- **Логи:** все операции и отказы пишутся через pino в stdout backend-контейнера, в консоль браузера ничего не выводится.
- **API** отдаёт готовые поля для UI: `isDefault`, `pinnedPlacementsCount`, `deactivationBlockedReason`. Маршрут `POST /api/tag-constants/:id/set-default`.

### 5.10 Модели сигналов (реализовано в 1.2)

- **Выбор моделей S3/S5/S6** — по паре «сегмент + версия констант показа»: на каждом уровне цепочки модель нужной версии приоритетнее. Активная модель — одна на пару «сегмент + версия».
- **Сегменты S6:** `{устройство}|instream_skippable | instream_non_skippable | outstream`, всего 9. Ключ строится **только** функциями `resolveS6SegmentKeys` и `buildS6SegmentKey` в `shared`. Резервная цепочка: новый сегмент → прежний (`skippable`/`non_skippable`; outstream → `non_skippable`) → часть без устройства → `global` → значения по умолчанию. В задаче 1.4 меняется только входной параметр функции (формат вместо `delivery_mode`).
- **Выборки рекалибровки:**
  - только `score_reliable = true` (IVT-вердикт `valid`);
  - без `CLIENT_CONTEXT_MISMATCH`;
  - для S1, S4 и S6 — только данные SDK (`measurement_mode <> 'legacy_tag'`);
  - S3, S5 и S7 обучаются на данных обоих режимов;
  - счётчики исключённых показов пишутся в лог.
- **Качество подбора S3/S6** — по стандарту S5: несошедшиеся модели не сохраняются, разбиение детерминированное (SHA-256 от `impression_id`).
- **Активные модели, обученные на данных тега,** остаются активными до ручной активации черновиков на данных SDK: S1 `desktop|static`, S3 `desktop|static`, S4 `desktop_banner`, S5 `desktop`.
- **Формулы, значения моделей, веса и калибровка весов не менялись.**

### 5.11 Невалидный трафик

Показы с ботами хранятся, видны в панели и CSV с вердиктом. В обучение моделей не попадают.
