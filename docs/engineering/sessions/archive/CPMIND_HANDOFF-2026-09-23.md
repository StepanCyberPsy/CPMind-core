## 2. Продукт

### 2.1 Назначение

**CPMind** — платформа измерения качества рекламного показа. Для каждого показа собираются 7 поведенческих сигналов (S1–S7). Каждый переводится в шкалу 0–100 калибруемой моделью, затем взвешенно объединяется в **CPMind Score (0–100)** с учётом фактора присутствия F_Presence и IVT-классификации (невалидный трафик).

### 2.2 Сигналы

| Сигнал | Что измеряет | Модель нормализации | Разбиение моделей |
|---|---|---|---|
| S1 | Время в зоне видимости | Weibull (MLE) | `устройство\|группа креатива` → группа → `global` |
| S2 | Доля экрана | Без калибруемой модели | — |
| S3 | Скорость и паттерн скролла | Логистическая регрессия (IRLS) | `устройство\|группа креатива` → группа → `global`; с учётом версии констант |
| S4 | Активность вкладки | Экспоненциальный штраф (λ, T_ref) | `desktop_banner`, `mobile_banner`, `desktop_video`, `mobile_video`, `default` |
| S5 | Взаимодействия | Логистическая регрессия | `desktop`, `mobile_tablet` → `global`; с учётом версии констант |
| S6 | Вовлечённость в видео и звук | Логистическая регрессия | `устройство\|группа размещения` (раздел 5.10); для баннеров `null` |
| S7 | Контекст страницы | Квантильные пороги | по устройству → `global` |

### 2.3 Формула Score

```
Score = (S1·w1 + S2·w2 + ... + S7·w7) × F_Presence × F_IVT
```

**Веса** — глобальная активная версия отдельно для баннеров и видео:
- баннеры: S1 0.30, S2 0.20, S3 0.15, S4 0.15, S5 0.15, S6 0.00, S7 0.05;
- видео: S1 0.15, S2 0.10, S3 0.10, S4 0.10, S5 0.10, S6 0.40, S7 0.05.

Вес недоступных (`null`) сигналов перераспределяется пропорционально. `F_Presence = 0`, если последнее событие зрителя было раньше порога `PRESENCE_IDLE_TIMEOUT_MS`. `F_IVT = 0` при вердикте `givt` или `sivt_confirmed`.

### 2.4 Три уровня настройки расчёта

| Уровень | Что определяет | Как выбирается |
|---|---|---|
| Константы сбора (`tag_constants_configs`, версии `v0…v4`, локально также `dev`) | 19 порогов сбора в браузере и `PRESENCE_IDLE_TIMEOUT_MS` на сервере | Версия по умолчанию (`is_default`) + необязательное закрепление в плейсменте |
| Модели сигналов (`s1_weibull_configs`, `s3/s5/s6_logistic_configs`, `s4_configs`, `s7_quantile_configs`) | Перевод сырого значения в 0–100 | Задача рекалибровки создаёт черновик, администратор вручную активирует. Применяется к сегменту, не к плейсменту |
| Веса (`weight_configs`) | Вклад S1–S7 в Score | Одна глобальная активная версия на категорию (баннер/видео) |

### 2.5 Режимы измерения

- **`legacy_tag`** — прежний встраиваемый тег (`packages/tag`). Больше не размещается, но данные и логика сохранены; 825 исторических показов в БД.
- **`full_cpmind_player`** — видео в плеере CPMind;
- **`full_direct_display`** — баннеры, включая HTML5;
- **`vast_only`** — VAST без плеера CPMind, не измеряется;
- **`partial_embedded_iframe`** — зарезервирован.

## 3. Архитектура

### 3.1 Монорепозиторий

| Пакет | Назначение |
|---|---|
| `shared` | Zod-схемы контрактов, типы, формулы нормализации и Score, сегментация моделей |
| `sdk` | Сбор сигналов S1–S7, присутствие, транспорт, сегментация показов |
| `tag` | Legacy-тег (сборка с константами версии через esbuild define) |
| `backend` | Fastify API: приём показов, scoring, IVT, доставка (embed/VAST/события), админка, фоновые задачи |
| `frontend` | Next.js 14, панель администратора и пользователя |
| `media-worker` | Обработка загрузок: видео (FFmpeg), баннеры, HTML5-бандлы |
| `embed` | Loader, подгружающий нужный runtime |
| `display-runtime` | Рендер баннеров (static/gif/HTML5) и измерение |
| `player` | Видеоплеер CPMind (VAST 4.3, in-stream/out-stream/sticky) |
| `creative-bridge` | Скрипт внутри HTML5-креатива: клики и взаимодействия → хост |
| `runtime-publisher` | Публикация runtime-бандлов в CDN (одноразовая задача при деплое) |

**Стек:** TypeScript, Node.js 22, Fastify, Next.js 14, PostgreSQL 16, Drizzle ORM (kit 0.22.8, orm 0.31.4), esbuild, FFmpeg, Docker, NGINX, pnpm 9.15.2 (**не обновлять**), Vitest 1.6.

### 3.2 Поток доставки

```
Издатель вставляет <script src="https://delivery.cpmind.tech/e/{token}.js">
   │
   ├─ backend: resolveEmbedScript
   │    ├─ резолв плейсмента по delivery_token
   │    ├─ выбор ролика из набора (ротация)
   │    ├─ создание ad_session (кроме in-stream)
   │    └─ отдаёт JS: конфигурация в window.__CPMIND_QUEUE__ + <script> loader с CDN
   │
   ├─ embed/loader: по creativeType подгружает display-runtime либо player
   │
   ├─ player (видео):
   │    ├─ in-stream: bindNativeContent слушает content video издателя,
   │    │              сессия запрашивается в момент вставки (POST /api/delivery/session)
   │    ├─ out-stream inpage: IntersectionObserver, загрузка при появлении,
   │    │              воспроизведение при 50% видимости
   │    ├─ out-stream sticky: position fixed в углу окна, загрузка сразу
   │    ├─ GET /vast/{token}?sid={adSessionId} → VAST 4.3 InLine
   │    └─ зацикливание out-stream: POST /api/delivery/advance → следующий ролик
   │
   └─ sdk: сбор S1–S7 → POST /api/collect (app.cpmind.tech)
```

### 3.3 Иерархия сессий

```
ad_session (ad_session_id)          — одна рекламная возможность
  └─ показ ролика (session_group_id) — конкретный креатив из набора, video_show_index
       └─ сегмент (impression_id)    — интервал измерения (разбивка по простою)
```

- **Баннер:** один показ, один или несколько сегментов.
- **In-stream:** один ролик на `ad_session`. Сессия создаётся в момент вставки, **не** при загрузке страницы.
- **Out-stream:** несколько показов роликов в одной сессии, каждый цикл — новый `session_group_id` с номером `video_show_index`.

### 3.4 Домены

| Домен | Назначение |
|---|---|
| `app.cpmind.tech` | Панель и API, приём показов (`/api/collect`) |
| `delivery.cpmind.tech` | Embed-скрипты, VAST, delivery-события, трекинг-пиксели |
| `creative.cpmind.tech` | Изолированный origin для HTML5-креативов (CSP `connect-src 'none'`) |
| `cdn.cpmind.tech` | CDN поверх бакета `cpmind-delivery-assets` |

## 4. Инженерный контракт и порядок работы

Действует `ENGINEERING_INSTRUCTIONS.md`. Ключевое:

- Только SOTA, production-ready, enterprise-grade код: без заглушек, допущений и макетов.
- Источник истины — реализованный код и зафиксированные решения. При нехватке контекста работа останавливается и запрашиваются конкретные файлы.
- Формат изменений: **Before/After**, последовательно, пункт за пунктом. В блоке Before нет сокращений через многоточие. Большие изменения — полная замена файла.
- Отступы: 4 пробела в новых файлах, в изменяемых — стиль файла (часть backend-файлов использует 2 пробела).
- Длинных разделительных строк нет. Вокруг операторов по одному пробелу. У многоаргументной функции каждый аргумент на отдельной строке.
- Комментарии в коде и ответы — **на русском языке**.
- Код валидируется до представления. Не ходить по кругу: исправления «задним числом» недопустимы.

**Порядок работы:** определение задачи → план реализации → согласование владельцем → реализация → валидация.

## 5. Принятые архитектурные решения

### 5.1 Таксономия размещений (реализована)

Два уровня: формат → подтип, один подтип на плейсмент.

| Формат | Подтипы | plcmt (OpenRTB 2.6) |
|---|---|---|
| `banner` | — | `null` |
| `instream` | `preroll`, `midroll`, `postroll`, `pauseroll` | 1 |
| `outstream` | `inpage`, `sticky` | 2 |

**Точки вставки in-stream:**
- `preroll` — первый `play` контента издателя;
- `midroll` — `timeupdate` на 50% длительности контента, один раз за просмотр;
- `postroll` — `ended` контента, контент не возобновляется;
- `pauseroll` — `play` после `pause` (при возобновлении, не в момент паузы).

**Out-stream:**
- `inpage` — встраивается в поток страницы, загрузка при попадании во вьюпорт, воспроизведение при 50% видимой площади;
- `sticky` — `position: fixed` в углу окна, монтируется в `document.body` (не в контейнер: `transform` у родителя сломал бы `fixed`), загрузка сразу.
- Оба зациклены: после завершения ролика вызывается `/api/delivery/advance` и начинается новый цикл.

**Прежняя модель `delivery_mode` сохраняется до шага 4.6** (раздел 9). `format`/`subtype` — источник истины, `delivery_mode` заполняется параллельно.

### 5.2 Набор роликов (реализован)

- Только видео; баннеры остаются с одним креативом.
- Все ролики — из одной кампании, принадлежат владельцу плейсмента.
- Таблица `placement_creative_set`: `placement_id`, `creative_id`, `weight_pct`, `display_order`.
- Сумма весов строго 100 (допуск 0.01 для долей, не делящихся нацело). Проверяется Zod-схемой; CHECK по агрегату в Postgres невозможен.
- **In-stream:** один ролик на рекламную возможность, взвешенный случайный выбор.
- **Out-stream:** `sequential` — по кругу 1→…→N→1; `weighted_random` — взвешенно случайно без повтора подряд. **Всегда зацикливается.**
- Каждый показ ролика — новый `session_group_id` и `video_show_index`.
- `placements.creative_id` остаётся `NOT NULL` и хранит **основной креатив** — первый ролик набора по `display_order`.

### 5.3 Звук и контролы (реализовано)

**Умолчание звука выводится из формата:**
- in-stream → стартует со звуком (`initial_muted = false`);
- out-stream → стартует без звука (`initial_muted = true`).

Пользователь может переопределить; флаг `initial_muted_overridden` отличает явный выбор от умолчания. При смене формата умолчание пересчитывается только если `overridden = false`.

**Профиль контролов по формату** (переопределения нет):

| Формат | Play | Seek | Skip | Volume | Close | Клавиатура |
|---|---|---|---|---|---|---|
| instream | да | да | по `skippable` | да | нет | Space, K, M, ←, → |
| outstream | нет | нет (индикатор без перемотки) | нет | да | да | только M |

Перемотка в out-stream исключена намеренно: иначе зритель проскакивает ролик, и S6 фиксирует `completion` без просмотра.

**Четыре состояния звука различаются:**

| Поле | Смысл |
|---|---|
| `initial_muted` | что запросил плейсмент |
| `start_muted` | фактическое состояние при первом старте |
| `muted_by_browser` | браузер принудительно заглушил при автозапуске |
| `unmuted_by_user` / `muted_by_user` | только действие зрителя |

При блокировке автозапуска со звуком плеер откатывается в muted; при ручном запуске запрошенное состояние восстанавливается с источником `player` (не `user`), чтобы не исказить S6.

### 5.4 Skip-таймер и перемотка (реализовано)

- Обратный отсчёт ведётся по **максимально достигнутой** позиции, а не по текущей: перемотка назад не запускает таймер заново.
- Перемотка вперёд ограничена позицией `skipOffsetSec`, пока кнопка не разблокирована — в обеих точках ввода: кнопки/клавиатура и полоса перемотки.
- Источник истины для `skippable` и `skipOffsetSec` — конфигурация доставки, VAST-разметка резервом. Проценты из VAST разворачиваются в секунды.
- Смещение, превышающее длительность ролика, делает его непропускаемым.

### 5.5 Идентификаторы (реализовано)

| Сущность | В показе | Отображается |
|---|---|---|
| Кампания | `campaign_key` в `impressions.campaign_id` | `campaigns.name` джойном по `campaign_ref_id` |
| Креатив | `creative_key` в `impressions.creative_id` | `creatives.name` джойном по `creative_ref_id` |

**Это отменяет прежнее решение** «`campaign_id` в показе — название кампании». Причина: название не проходит `SAFE_ID_REGEX` (пробелы), из-за чего в одной колонке сосуществовали два несовместимых формата; переименование кампании разрывало историю.

- Ключи задаются пользователем опционально, иначе генерируются (16 hex).
- Уникальность: `(user_id, campaign_key)`, `(user_id, lower(name))`, `(campaign_id, creative_key)`.
- Конфликты различаются по имени нарушенного ограничения и дают 409 с кодами `CAMPAIGN_NAME_TAKEN`, `CAMPAIGN_KEY_TAKEN`, `CREATIVE_KEY_TAKEN`.
- Для legacy-показов ссылок нет, названия `null` — в панели показывается ключ.

### 5.6 Домен площадки (реализовано)

Цепочка приоритета для hosted-показа:
1. `placements.publisher_domain` — переопределение администратором;
2. `ad_sessions.publisher_domain` — извлечён сервером из `Referer` при выдаче;
3. `payload.publisher_domain` — определён SDK на странице;
4. `null`.

Расхождение источника 2 или 3 с клиентским значением помечается флагом `PUBLISHER_DOMAIN_MISMATCH` (при переопределении в плейсменте сверка не производится).

**Режимы `allowed_domains`** (`placements.domain_enforcement`, умолчание `monitor`):

| Режим | Список пуст | Домен совпал | Не совпал | Домен неизвестен |
|---|---|---|---|---|
| `off` | принят | принят | принят | принят |
| `monitor` | принят | принят | принят + `ALLOWED_DOMAIN_MISMATCH` | принят |
| `block` | принят | принят | **422** | принят |

Поддомены разрешённого домена принимаются. Неизвестный домен не блокируется ни в одном режиме — `Referrer-Policy: no-referrer` у издателя не должна отклонять достоверные показы. Проверка выполняется на приёме показа, не на выдаче.

### 5.7 Нарушения контекста при приёме показа

**Жёсткий отказ (422):** сессия не найдена; чужой владелец; сессия старше `AD_SESSION_TTL_HOURS` (по умолчанию 24 ч, максимум 168 ч); `vast_only`; неполный контекст; `PUBLISHER_DOMAIN_NOT_ALLOWED`.

**Мягко (показ принимается с флагом в `context_violations`):** плейсмент неактивен; креатив сменился; `CLIENT_CONTEXT_MISMATCH`; `PUBLISHER_DOMAIN_MISMATCH`; `ALLOWED_DOMAIN_MISMATCH`.

### 5.8 Поведение сбора

| Событие | Поведение |
|---|---|
| Вкладка скрыта | Промежуточный снимок (тот же `impression_id`, `is_checkpoint = true`), измерение продолжается |
| `pagehide`, завершение | Финальная отправка с причиной (`finalization_reason`) |
| Клик | Промежуточный снимок не чаще раза в секунду, **не** завершение |
| Сервер: upsert снимка | `ON CONFLICT (impression_id) DO UPDATE` только если строка — снимок, `ad_session_id` совпадает и `timestamp_end` не уменьшается |
| Видео не стартовало | Записи в `impressions` нет, в `ad_session` пишется `autoplay_outcome = blocked` |
| Досмотр S6 | Только фактически просмотренный отрезок (`watchedFrontierSec`), перемотка вперёд не засчитывается |
| Окно измерения hosted | Начинается с подтверждённого первого кадра |
| Скрытая вкладка (out-stream, sticky) | Воспроизведение приостанавливается — иначе S6 копит досмотр в невидимой вкладке, противореча S4 |

**Правило 1.D: показ не создаётся без фактического старта воспроизведения.** Для автозапуска — по подтверждённому первому кадру; при `autoplay_mode = 'click_to_play'` — только после действия зрителя. Без автозапуска контролы видны с первого кадра и не скрываются до начала воспроизведения (на сенсорных устройствах нет `pointermove`).

### 5.9 Измерение HTML5 (двухуровневое доверие)

Код рекламодателя исполняется в одном окне с мостом и может подделать любое сообщение. События моста принимаются только при подтверждении со стороны страницы:

| Событие моста | Устройство с курсором | Сенсорное устройство |
|---|---|---|
| `click`, `tap` | Курсор над iframe или фокус iframe; `userActivation` не `false` | `userActivation.isActive` (или фокус) и iframe виден не менее чем на 50% |
| `activity`, `swipe`, `zoom` | Только курсор над iframe | iframe виден и прошло не более 30 с с последнего доверенного события |

Отклонённые события попадают только в диагностическое поле `unconfirmed_frame_events`. HTML5 → `full_direct_display`. Протокол моста — версия 2, совместим с версией 1.

### 5.10 Версии констант сбора

- Ровно одна **версия по умолчанию** (`is_default`), она всегда активна. Новая версия создаётся активной, но не становится версией по умолчанию.
- **Закрепление версии в плейсменте** (`placements.tag_constants_config_id`) — только администратор, иначе 403. Закреплять можно только активную версию.
- **Деактивация запрещена (409)** для версии по умолчанию и для версии, закреплённой за плейсментами. Версии никогда не удаляются.
- Версия фиксируется в `ad_sessions.tag_constants_version`; показы идущих сессий принимаются по ней в пределах окна приёма даже после деактивации.
- **Конкурентность:** advisory-lock плюс `FOR UPDATE` при деактивации и смене версии по умолчанию, `FOR SHARE` при закреплении.
- `bootstrapTagConstants` при старте восстанавливает версию по умолчанию (последняя активная по `created_at`), если её нет. Ручной `UPDATE` в миграции не требуется.

### 5.11 Модели сигналов

- **Выбор моделей S3/S5/S6** — по паре «сегмент + версия констант показа». Активная модель — одна на пару.
- **Сегменты S6:** `{устройство}|instream_skippable | instream_non_skippable | outstream`, всего 9. Ключ строится **только** функциями `resolveS6SegmentKeys` и `buildS6SegmentKey` в `shared`.
- **Подтип на сегмент S6 не влияет** — решение текущей сессии: точка вставки in-stream и способ закрепления out-stream не меняют характер вовлечённости. Дробление на 8 групп размыло бы выборку при пороге 1000 показов на сегмент.
- **Выборки рекалибровки:** только `score_reliable = true`; без `CLIENT_CONTEXT_MISMATCH`; для S1, S4 и S6 — только данные SDK; S3, S5 и S7 обучаются на данных обоих режимов. Для S6 дополнительно требуется непустой `s6_duration_sec`.
- **Качество подбора** — несошедшиеся модели не сохраняются, разбиение детерминированное (SHA-256 от `impression_id`).

### 5.12 Контент-адресованное хранилище

Ассеты хранятся по ключу `assets/sha256/{ab}/{cd}/{sha256}.{ext}`, HTML5-бандлы — `html5/{ab}/{cd}/{sha256}/{путь}`.

**Гонка GC ↔ media-worker закрыта:** загрузка в хранилище выполняется всегда, даже при найденном по SHA-256 ассете. Ключ контент-адресован, повторная запись тех же байт идемпотентна. Прежнее поведение (пропуск загрузки) допускало сценарий, где GC удалял объект между поиском и публикацией, и креатив становился `ready` с ключом, по которому раздача отдаёт 404.

- **Контейнеры:** nginx, backend, frontend, postgres, backup, media-worker, runtime-publisher (одноразовая задача).
- **Бэкапы:** `pg_dump` ежедневно в 02:00 UTC, хранение 30 дней, локально на той же машине.

### 11.2 Зафиксированные расхождения

| № | Расхождение |
|---|---|
| 1 | Прежний handoff утверждал, что права `storage.editor` на source- и delivery-бакеты выданы backend. Фактически `cpmind-backend-signer` присутствует только в `cpmind-upload-staging` |
| 2 | `AD_SESSION_TTL_HOURS` отсутствует в `.env`; compose подставляет дефолт 24. Правило отказа 422 работает на неявном значении |
| 3 | Версии рантаймов передаются двумя механизмами: backend — runtime-переменные, `runtime-publisher` — build args, зашитые в образ. Смена версии в `.env` требует пересборки publisher'а |
| 4 | `BRIDGE_VERSION` не передаётся backend'у. Отдельно: это версия артефакта на CDN, тогда как протокол моста имеет собственную версию 2 — две оси с пересекающимися номерами |
| 5 | CORS staging-бакета: Allowed Origin указан как `app.cpmind.tech` **без схемы**. Origin в браузере всегда со схемой — требует проверки в консоли |
| 6 | `COLLECT_ENDPOINT` указывает на `app.cpmind.tech`, embed — на `delivery.cpmind.tech`: beacon всегда кросс-доменный. CORS для `/api/collect` обеспечивается `@fastify/cors` с `origin: true, credentials: true` |
| 7 | CSP панели не содержит `delivery.cpmind.tech` ни в `connect-src`, ни в `frame-src`. Предпросмотр через delivery-домен будет заблокирован браузером |
| 8 | Содержимое бакетов не соответствует работающей раздаче: `cpmind-source-assets` пуст, `cpmind-delivery-assets` содержит только `staging/` и `health/`. Пути публикации `_v2` требуют проверки по `runtime-publisher/src/` |
| 9 | Политика `AllowAWSServices` на delivery-бакете: `Allow` для `*` на действие `*` по условию `PrincipalIsAWSService = true` |
| 10 | `media-worker` использует tmpfs 10 ГБ — это оперативная память VM. `WORKER_CONCURRENCY = 1`, обработка строго последовательная |

## 12. План деплоя

1. `pg_dump` — ручной бэкап.
2. Остановка сервисов.
3. **Очистка БД** через `docker compose exec postgres psql`:
   - **удаляются:** `campaigns`, `creatives`, `creative_versions`, `creative_version_assets`, `creative_processing_jobs`, `upload_sessions`, `placements`, `placement_creative_set`, `ad_sessions`, `assets`, hosted-показы;
   - **сохраняются:** `users`, `tags`, legacy-показы, все конфигурационные таблицы.
4. В `.env` установить `2` для `LOADER_RUNTIME_VERSION`, `DISPLAY_RUNTIME_VERSION`, `PLAYER_RUNTIME_VERSION` и `BRIDGE_VERSION`. Бандлы `_v2` публикуются рядом с `_v1`, чтобы избежать конфликтов кэша CDN. **Требуется пересборка `runtime-publisher`** — версии зашиты в образ build args.
5. Деплой с применением миграций 0023–0027.
6. Проверка данных после миграции 0026:
   ```sql
   SELECT mode, format, subtype, COUNT(*) FROM placements GROUP BY 1,2,3;
   SELECT delivery_mode, format, subtype, COUNT(*) FROM impressions GROUP BY 1,2,3;
   ```
7. E2E-матрица по всем типам креативов и размещений.
8. SQL-сверка `ad_sessions` и `impressions`: одна сессия на показ, корректный `measurement_mode`, заполненный `measurement_started_at`, квартили S6, `video_show_index`.
9. **После подтверждения** — отдельная миграция снятия `delivery_mode` (раздел 9.3).

## 13. Точка входа следующей сессии

**Приоритет 1 — стендовая проверка блоков 1–7.** Ни одно изменение плеера не проверено на живых данных. Минимальный сценарий:

- in-stream со звуком: иконка корректна с первого кадра, квартили S6 фиксируются, кнопка Skip появляется и разблокируется по отсчёту;
- перемотка назад не увеличивает skip-таймер, перемотка вперёд не приближает разблокировку;
- out-stream: контролов кроме звука и закрытия нет, полоса прогресса неинтерактивна;
- out-stream в узком окне (высота поверхности больше вьюпорта): ролик стартует;
- переключение вкладки: воспроизведение приостанавливается;
- набор из двух роликов: цикл меняет ролик, `video_show_index` растёт;
- sticky: закрепляется в углу, не уезжает при прокрутке.
