### P-18 — калибровка детекции свайпа/zoom (полностью, включая ранее отложенную часть)

**Решение клиента:** только пороги детекции, балл уровня S5 (90) за жест не меняется.

**Было:** `SWIPE_MIN_DISTANCE_PX = 30`, инлайн-порог pinch-fallback `10`, `gesturechange` ставил `zoom = true` без какой-либо проверки амплитуды жеста.

**Стало:**
- `SWIPE_MIN_DISTANCE_PX` 30 → 60.
- Pinch-fallback порог вынесен в именованную константу `PINCH_DELTA_MIN_PX` (значение не менялось — 10).
- Добавлена проверка `Math.abs(scale - 1) > GESTURE_SCALE_DELTA_MIN` (0.15) для `gesturechange` — ранее этот путь срабатывал при любом двупальцевом касании на iOS Safari, независимо от двупальцевого touch-fallback.
- Дополнительно вынесены в константы: допуск смещения для tap (`TAP_MAX_OFFSET_PX`), максимальная длительность tap (`TAP_MAX_DURATION_MS`), порог дедупликации mousemove (`MOUSE_MOVE_DEDUP_PX`) — значения не менялись.

**Файл:** `packages/tag/src/signals/s5.ts`

**Статус:** реализовано, `tsc --noEmit` и билд тега чистые. Функциональный тест на стендах B04/B05b/C03 — за клиентом, в этой сессии не проводился.

### P-15 — скользящее окно F_Presence + сегментация показа по простою

**Решение клиента:** обнулять Score, если нет событий пользователя в последние 60 секунд показа, независимо от количества событий до этого. Дополнительно: непрерывный простой ≥60 сек в середине показа разрывает показ на отдельные сегменты, не засчитывая простой как часть единого просмотра. Короткие полностью пассивные показы (<60 сек, событий 0) — оставлены без изменений, как и раньше.

**Backend — `packages/shared/src/scoring/score.ts`:**

Было: `presence_failed = (time_since_last_event_ms > 60000) AND (events_count_during_impression === 0)`.

Стало: `presence_failed = time_since_last_event_ms > PRESENCE_IDLE_THRESHOLD_MS` (константа, значение 60000). AND-условие убрано — обнуление срабатывает по факту простоя независимо от активности до него.

**Сопутствующий найденный и закрытый баг — `packages/backend/src/services/scoring.ts`:**

`signalsRaw` собирался только из `payload.signals`, без `payload.presence` — прямое нарушение §6.1 ТЗ ("signals_raw — все сырые поля, как пришли от тега"). Presence-поля физически не попадали в БД, поэтому CSV-экспорт показывал их пустыми на стенде B02 клиента, независимо от логики обнуления. Исправлено: `signalsRaw: { ...payload.signals, presence: payload.presence }`.

**Тег — сегментация показа:**

- `packages/tag/src/signals/presence.ts`: добавлен debounce-таймер простоя 60 сек, перезапускается на каждом raw-событии. По истечении вызывает `onIdle()`.
- `packages/tag/src/segment.ts` (новый файл): оркестратор — финализация и отправка текущего сегмента, сброс сессии, вызов `resetSegmentSX()` каждого сигнального модуля.
- `packages/tag/src/transport/send.ts`: `finalizeAndSend()` получил параметр `isFinal` — при разрыве по простою `session.sent` не залипает, позволяя последующим сегментам тоже отправиться.
- `packages/tag/src/session.ts`: `resetSessionForNewSegment()` — сброс полей сессии in-place (не пересоздание объекта — иначе уже зарегистрированные обработчики событий продолжили бы писать в старый объект).
- `packages/tag/src/signals/{s1,s2,s3,s4,s5,s7}.ts`: добавлены `resetSegmentSX()` для каждого сигнала. Отдельно: `s1.ts` пересоздает `IntersectionObserver` (без этого новый сегмент не получил бы intersection-callback, если позиция баннера не менялась); `s5.ts` сбрасывает приватные замыкания (траектория курсора, touch-state), не достижимые через `session`; `s7.ts` не сбрасывает `is_above_the_fold` — свойство загрузки страницы, не сегмента.
- `packages/shared/src/schemas/impression.ts`, `packages/backend/src/db/schema.ts`: новые поля `session_group_id`, `segment_index`. Опциональны на входе (обратная совместимость со старыми закэшированными версиями тега), с фолбэком в `scoring.ts` (`?? impression_id`, `?? 0`).
- Миграция `0002_elite_puppet_master.sql`: `ADD COLUMN session_group_id`, `segment_index` + индекс.

**Граница объема, согласованная отдельно:** если вкладка хотя бы раз была свернута (`visibilitychange → hidden`), сегментация по простою для этой страницы отключается — обработчики presence снимаются вместе с финальной отправкой. Остается только финальная отправка при закрытии. Не дефект, осознанное ограничение.

**Файлы:** `score.ts`, `scoring.ts`, `impression.ts`, `db/schema.ts`, `services/impressions.ts`, `routes/impressions.ts`, `services/csv.ts` (backend); `presence.ts`, `segment.ts`, `session.ts`, `types.ts`, `send.ts`, `signals/*.ts`, `index.ts` (тег); `Filters.tsx`, `ImpressionsTable.tsx`, `ImpressionDetail.tsx`, `lib/api.ts`, `lib/types.ts`, `app/impressions/[id]/page.tsx` (панель).

**Статус:**
- Backend (формула, хранение `presence`, фильтр по `session_group_id`) — протестировано curl + прямым SQL на нескольких сценариях, включая реальную историю с 5 переключениями вкладки.
- Тег — подтверждено живым браузерным тестом: переход `segment_index 0 → 1` с совпадающим `session_group_id`, новый `impression_id`, S1 нового сегмента посчитан с нуля (не унаследовал время из прошлого сегмента — подтверждено количественным совпадением временного разрыва между отправками и значением S1 нового сегмента). Множественные простои за один показ (`segment_index 0, 1, 2…`) и mobile/touch путь сегментации в этой сессии не тестировались.
- Панель аналитика — `tsc --noEmit` чистый, визуальный/функциональный тест в браузере не проводился.

### P-05 — рассинхрон таймеров S4 (`tab_active_time_ms` / `tab_total_time_ms`)

Не было в списке клиентского тестирования — найдено и закрыто в ходе работы над P-15 при ручном браузерном тесте (зафиксировано воспроизведение 180.3% активности).

**Причина:** `tabSessionStart` (`s4.ts`) стартует от момента загрузки страницы, `timestampStart` (`s1.ts`) — от момента, когда баннер впервые становится видимым на ≥50%. Старая финализация в `buildPayload()` обрезала результат через `Math.min(rawTabActiveTimeMs, tabTotalTimeMs)` — маскируя рассинхрон потолком 100%, не устраняя его.

**Решение:** `computeActiveTimeMsInRange()` — пересчет активного времени напрямую из `visibilityStateHistory`, строго в границах `[timestampStart, now]`. Результат математически не может выйти за пределы диапазона.

**Найдена и закрыта вторая точка той же ошибки** — дебаг-оверлей (`debug/overlay.ts`) использовал отдельную, независимо написанную формулу без `Math.min`, показывавшую те же 180.3%/167.1% визуально тестировщику. Обе точки теперь читают из одной и той же функции.

**Файлы:** `packages/tag/src/session.ts`, `packages/tag/src/debug/overlay.ts`.

**Статус:** протестировано на реальной истории переключений вкладки (5 переходов `visible`/`hidden`) — результат подтвержден арифметически (разница `total - active` совпала с длительностью зафиксированного провала видимости). Подтверждено и в backend-payload, и в дебаг-оверлее раздельно.
